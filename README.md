# AgriSense Edge — Android camera app + ExecuTorch model export

AgriSense Edge is the on-device deployment part of the AgriSense plant-disease project. It contains a React Native camera app, Android/iOS ExecuTorch bridge source, and Python scripts that export the CNN classifier and U-Net segmentation models to `.pte` files.

**Important:** the original ZIP did not contain the trained model checkpoints (`cnn_classifier.pt`, `unet_segmentation.pt`) or exported `.pte` files. The app source is included, but real AI diagnosis will not work until those model files are supplied and exported. You can still build the Android app and use its clearly labelled **camera preview-only** mode without model files.

## Project layout

```text
agrisense-edge/
├── export/
│   ├── models.py                 # CNN + MiniUNet definitions
│   ├── export_pte.py             # PyTorch checkpoint -> ExecuTorch .pte
│   ├── verify_parity.py           # PyTorch vs .pte output comparison
│   ├── benchmark_pte.py           # desktop runtime benchmark
│   └── requirements.txt
├── mobile/
│   ├── AgriSenseMobile/           # app source + native bridge source
│   └── AgriSenseMobileApp/        # generated by setup-android.ps1
├── models/checkpoints/            # put trained .pt files here (not included)
└── scripts/
    ├── setup-android.ps1          # creates the missing RN native project
    ├── copy-models.ps1            # copies exported .pte files into Android assets
    └── check-environment.ps1
```

## A. Run the Android app in VS Code (Windows 11)

### 1. Install the required tools

Install these before building:

- **Node.js 22 LTS** and npm.
- **JDK 17**. Configure `JAVA_HOME` and add `%JAVA_HOME%\bin` to `Path`.
- **Android Studio** with Android SDK Platform, Android SDK Build-Tools, Platform-Tools, and an Android emulator image. Set `ANDROID_HOME` (or `ANDROID_SDK_ROOT`) to your SDK directory and add `platform-tools` to `Path`.
- **VS Code** with the React Native Tools extension (optional, but useful).

Open Android Studio once, install the SDK components, and create/start an Android emulator. A physical Android phone with Developer Options and USB debugging enabled also works. For camera capture, a physical phone is recommended.

### 2. Open the project

1. Extract the ZIP file.
2. Open the extracted `agrisense-edge` folder in VS Code (`File → Open Folder`).
3. Open a VS Code PowerShell terminal (`Terminal → New Terminal`).
4. Check the installed tools:

```powershell
.\scripts\check-environment.ps1
```

### 3. Generate the complete React Native Android project

The ZIP has the React Native source and native bridge files, but does not have the Android Gradle wrapper / app scaffold. Generate them with the included script:

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\scripts\setup-android.ps1
```

The script creates `mobile\AgriSenseMobileApp`, copies the camera UI and native bridge, installs the JavaScript packages, registers the ExecuTorch package in `MainApplication.kt`, adds the camera permission and ExecuTorch Android dependency, and creates the model-assets folder.

The scaffold uses React Native 0.75.4 with its corresponding Community CLI 14.1.x line. The setup command needs an internet connection because npm must download the React Native template and packages.

### 4. Run the app

Start an Android emulator from Android Studio, or connect your Android phone with USB debugging enabled. Then, in the VS Code terminal:

```powershell
cd .\mobile\AgriSenseMobileApp
npm run android
```

The first Gradle build can take several minutes and will download Android dependencies. Keep the phone/emulator unlocked and approve the camera permission request.

If Metro does not start automatically, use two terminals:

**Terminal 1**

```powershell
cd .\mobile\AgriSenseMobileApp
npm start
```

**Terminal 2**

```powershell
cd .\mobile\AgriSenseMobileApp
npm run android
```

When model files are not installed, the app shows a model-load error. Choose **Open camera preview only** to test the camera and photo-preview flow. This mode does not run AI and must not be used for crop-treatment decisions.

## B. Add the trained AI models for real diagnosis

### 1. Locate the trained checkpoints

You need both of these files from the AgriSense training project:

```text
cnn_classifier.pt
unet_segmentation.pt
```

They were not present in the ZIP uploaded for this task. Put them in one folder, for example:

```text
agrisense-edge/models/checkpoints/
├── cnn_classifier.pt
└── unet_segmentation.pt
```

The exporter expects raw state dictionaries matching `export/models.py`. Check that the class order (`healthy`, `leaf_blight`, `leaf_rust`, `powdery_mildew`), input size (64×64), RGB channel order, and normalization match the training pipeline.

### 2. Prepare the export environment

The bundled exporter targets the ExecuTorch 0.4 API. The official 0.4 setup documentation lists Windows Subsystem for Linux (WSL) as the Windows route, so use **WSL2 + Ubuntu** for the export step rather than a regular Windows PowerShell environment. Open the project folder in VS Code using the WSL extension, then run in the WSL terminal:

```bash
cd /mnt/c/path/to/agrisense-edge
python3.10 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
pip install -r export/requirements.txt
```

If Python 3.10 is not installed in Ubuntu, install it before creating the environment. The ExecuTorch release and all Python exporter packages must stay version-aligned.

### 3. Export the models

From the project root in the WSL terminal:

```bash
python export/export_pte.py \
  --checkpoint-dir models/checkpoints \
  --out-dir export/pte
```

Expected output files (INT8 export may be skipped if the quantization step fails):

```text
export/pte/
├── cnn_classifier_fp32.pte
├── unet_segmentation_fp32.pte
├── cnn_classifier_int8.pte       # optional
├── unet_segmentation_int8.pte    # optional
└── export_manifest.json
```

### 4. Copy the `.pte` files into the Android app

Run this from a Windows PowerShell terminal at the project root. Use the Windows path to the `export\pte` folder (for a WSL project on the C: drive, it will normally be inside that drive):

```powershell
.\scripts\copy-models.ps1 -PteDir ".\export\pte"
```

The script requires both FP32 files and copies INT8 files when they exist. Then rebuild the app:

```powershell
cd .\mobile\AgriSenseMobileApp
npm run android
```

FP32 is selected by default. Use the on-screen model switch only when **both** INT8 files have been copied.

### 5. Verify and benchmark exported models

Run in the same activated WSL Python environment:

```bash
python export/verify_parity.py \
  --checkpoint-dir models/checkpoints \
  --pte-dir export/pte

python export/benchmark_pte.py \
  --checkpoint-dir models/checkpoints \
  --pte-dir export/pte \
  --n-runs 50 --warmup 10
```

The benchmark is a desktop/WSL proxy, not a phone latency measurement. Use the latency reported by the Android app for on-device results. Evaluate with held-out real leaf images before using any accuracy or Dice score in a report; synthetic calibration data is only a smoke-test/demo default.

## C. iOS build notes

The iOS bridge source and Podfile snippet are included, but the ZIP does not include a generated Xcode project. Building iOS requires macOS and Xcode; it cannot be built from Windows. Generate a React Native iOS scaffold on a Mac, integrate the Swift/Objective-C bridge, add camera permission text to `Info.plist`, add the `.pte` files to Copy Bundle Resources, and use the same ExecuTorch runtime release as the exporter.

## Troubleshooting

| Problem | What to check |
|---|---|
| `node` / `npm` not found | Install Node.js 22 LTS and restart VS Code. |
| `JAVA_HOME` not set or Gradle Java error | Install JDK 17 and point `JAVA_HOME` to it. |
| Android device not listed | Start the emulator or enable USB debugging; check `adb devices`. |
| Android SDK location error | Install SDK Platform/Build-Tools in Android Studio and set `ANDROID_HOME`. |
| Camera permission denied | Enable Camera permission in Android Settings for AgriSenseMobile. |
| `MODEL_LOAD_FAILED` | Check that both selected-mode `.pte` files exist in `android/app/src/main/assets/models/`. |
| No `MainApplication.kt` / setup script error | Make sure the React Native scaffold generated successfully; remove a partially generated `mobile/AgriSenseMobileApp` folder and rerun the setup script. |
| ExecuTorch export import or quantization error | Keep the exporter dependency versions aligned and check the ExecuTorch 0.4 export documentation. INT8 is optional; FP32 export is the baseline. |

## What is and is not verified

The source ZIP contained the React Native screens, TypeScript bridge wrapper, Kotlin/Swift bridge code, and Python export utilities. I updated model-mode switching so FP32/INT8 selection reloads the correct native modules, added clearer missing-native-module errors, and added a truthful preview-only path when model artifacts are absent. I also added a Windows setup script that generates the missing React Native Android scaffold.

I could not execute the Android Gradle build or a device camera test in this environment. The `.pt` checkpoints were not included, so no `.pte` artifacts or real model predictions are supplied. Complete the Android build on your machine and verify model preprocessing against your training pipeline before relying on any diagnosis.
